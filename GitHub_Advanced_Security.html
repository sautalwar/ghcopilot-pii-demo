GitHub Advanced Security is a suite of security tools designed to help developers find and fix vulnerabilities directly in their development workflow. The key word here is developer-first. These aren't security tools that slow you down or require you to leave your GitHub environment. GHAS consists of three core components: code scanning, secret scanning, and dependency review. These work together to protect different aspects of your code. It's free for public repositories, but for private and internal repositories you'll need a GitHub Advanced Security license.

Code scanning analyzes your source code to find security vulnerabilities and coding errors before you deploy. It uses static analysis, which means it examines your code without actually running it. The primary engine behind code scanning is CodeQL, GitHub's own semantic code analysis engine. But you're not limited to CodeQL — you can also integrate third-party tools that output results in a SARIF format. Code scanning can be configured to run automatically on every push or pull request, and results appear directly in the pull request and through the security tab. And the best part — it integrates with GitHub Copilot AutoFix, which can automatically suggest fixes for the vulnerabilities that it finds.

Secret Scanning

Prevent credential leaks before they cause damage

🔍 Comprehensive Scanning
  • Scans entire repo including Git history
  • Covers issues, PRs & wikis
  • Detects 200+ secret types
  • Custom regex pattern support
🤝 Partner Program
  • 150+ service provider partners
  • Automatic provider notification
  • Credential revocation workflows
  • Organization-wide visibility
🛡️ Push Protection
  • Blocks pushes containing secrets
  • Proactive security enforcement
  • Prevents secrets from entering repo
  • Bypass with audit trail
Secret scanning is crucial for preventing credential leaks. It automatically searches your entire repository, including your Git history, issues, and pull requests for sensitive information such as API keys, tokens, and passwords. It currently detects over 200 different types of secrets and works with about 150 different service providers through GitHub's partner program. When a secret is detected, GitHub can even notify the service provider directly so they can take action like revoking the credentials. You can also create your own regular expressions for secrets that you want to detect. But here's the really powerful part — push protection. Push protection actively blocks the pushes that contain detected secrets. It's proactive security that stops the problems before they start.

Dependency Review

Secure your software supply chain

Understand how dependency changes in pull requests impact your security posture. Catch supply chain risks before they reach production.

📊

Analyzes Dependency Changes in PRs

Scans added and updated dependencies and shows known vulnerabilities associated with them.

🛡️

Supply Chain Risk Prevention

Identifies vulnerable packages before they enter your codebase. Integrates with GitHub Advisory Database.

✅

Pre-Merge Security Checks

Integrates with GitHub Actions to fail PRs that introduce high severity vulnerabilities.

Dependency review focuses on your software supply chain security. This feature helps you understand how dependency changes in pull requests might impact your security posture. When someone creates a pull request that adds or updates a dependency, dependency review scans those changes and shows you any known vulnerabilities in the new or updated packages. It integrates with GitHub Actions, so you can actually fail a pull request if it introduces a high severity vulnerability. This catches supply chain risks before they're merged into your main branch. It's much easier to address a vulnerable dependency in a pull request than to deal with it after it's already in production.
